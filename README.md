## 1. Overview & Project Goals

This repository contains our implementation for Project 10 (CS60075 NLP, Group 29) on the Natural Questions Open dataset. We build and evaluate three progressive open-domain QA pipelines on a frozen index of 45,029 Wikipedia passages:

- **Task 1: Classical BM25 Baseline**: Lexical retrieval using `rank_bm25` (with $k_1=1.5, b=0.75$, top-5 passages), followed by sentence selection using question unigram overlap and rule-based extraction of the longest noun phrase or numeric span.
- **Task 2: Dense RAG**: Dense bi-encoder retrieval using `sentence-transformers/all-MiniLM-L6-v2` with an exact FAISS cosine inner-product index, conditioned on top-5 passages (truncated to 200 tokens each) and generated by `Qwen/Qwen2.5-1.5B-Instruct` with greedy decoding.
- **Task 3: Hybrid Fusion & Groundedness**: Combines BM25 and dense candidate pools using Reciprocal Rank Fusion (RRF, $c=60$), followed by a stopword-filtered lexical overlap check ($\tau=0.5$) to catch ungrounded model hallucinations.

All tasks are evaluated on the exact same 300 validation questions sampled from Natural Questions Open (seed 42).

## 3. Pipeline Implementation Details

### 3.1 Task 1: Classical Lexical Retrieve-and-Extract Baseline
- **BM25 Search**: Uses `rank_bm25.BM25Okapi` with lowercase whitespace tokenization ($k_1=1.5, b=0.75$). For each question, we retrieve the top 5 passages.
- **Multi-Passage Sentence Selection**: We split all sentences in the retrieved top-5 passages using `nltk.sent_tokenize`. We count unigram overlap $|W_Q \cap W_S|$ against the question words and choose the highest-scoring sentence.
- **Rule-Based Extraction**:
  - We tag POS tags and extract noun phrases with an NLTK chunk parser using `NP: {<DT|PRP$>?<JJ.*|VBG|VBN>*<NN.*>+}`.
  - In parallel, regex matches numbers, years, percentages, and ordinals.
  - We pick the candidate with the longest character length.

### 3.2 Task 2: Dense Retrieval-Augmented Generation (RAG)
- **Dense Vector Search**: We encode queries and passages with `sentence-transformers/all-MiniLM-L6-v2` into 384-dimensional vectors. Embeddings are $L_2$-normalized so cosine similarity equals inner product, evaluated with a FAISS `IndexFlatIP` index over the 45,029 passages.
- **Passage Truncation**: Top 5 passages are truncated to at most 200 whitespace tokens prior to prompt assembly, adhering to the context budget.
- **Generator Setup**: We run `Qwen/Qwen2.5-1.5B-Instruct` under deterministic greedy decoding (`do_sample=False, temperature=0.0`, `max_new_tokens=64`), prompting for direct, short answers.

### 3.3 Task 3: Hybrid Retrieval (RRF) & Groundedness Verification
- **Reciprocal Rank Fusion**: We take top-50 candidate lists from BM25 and dense retrieval and merge them with RRF:
  $$\text{Score}_{\text{RRF}}(d) = \sum_{m \in \{\text{BM25}, \text{Dense}\}} \frac{1}{60 + r_m(d)}$$
  The top 5 fused passages are passed to the generator.
- **Groundedness Check**: We compute the unigram overlap between the predicted answer and the retrieved passages, filtering out 24 common English stopwords (`the`, `of`, `in`, `at`, etc.).
- **Threshold Gating**: If content-word overlap is $\ge 0.5$, the answer is accepted. If overlap is $< 0.5$, the answer is flagged as ungrounded and abstained (`[UNGROUNDED / ABSTAINED]`).

## 6. Error Analysis & Failure Modes

We categorized all non-matching predictions across the 300 validation questions into four failure categories:

```text
1. RETRIEVAL FAILURE        (39.00%): Gold answer absent from top-5 context passages.
2. EXTRACTION / MISATTRIB   (19.33%): Evidence contained the answer, but model picked the wrong entity.
3. BOUNDARY / PARTIAL MATCH (9.00%) : Non-zero token overlap (F1 > 0), but missed exact string match.
4. HALLUCINATION / PRIOR    (5.33%) : Model synthesized an answer ungrounded in the retrieved evidence.
```
